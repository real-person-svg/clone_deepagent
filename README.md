# Agent Studio · 商业化竞品研究工作台

React + TypeScript + SQLite 的本机研究应用，支持真实模型、公开网页采集、资料导入、带引用报告和定期来源巡检。新工作空间没有预置竞品、价格或研究结论。

## 启动

需要 Node.js 22.16+（推荐 24）和 pnpm 10：

```sh
pnpm install --registry=https://registry.npmjs.org
cp .env.example .env
```

在本机 `.env` 配置兼容 Chat Completions 的模型服务：

```dotenv
MODEL_BASE_URL=https://your-provider.example/v1
MODEL_NAME=your-model-name
MODEL_API_KEY=
MODEL_TIMEOUT_MS=120000
```

填写自己的密钥；支持不需要密钥的本机兼容模型服务。接口需要支持 SSE、原生 tools 调用和流式 usage。密钥仅在服务端使用，`.env`、私钥、本地数据库、依赖和构建目录均已加入 Git 忽略规则。未配置模型时可以管理资料，但不能执行研究或订阅。

```sh
pnpm dev
```

访问 [本机工作台](http://127.0.0.1:5173)，API 默认监听 `127.0.0.1:4317`。生产构建和本机启动：

```sh
pnpm build
pnpm start
```

构建后访问 [本机服务](http://127.0.0.1:4317)。修改源码后需要重新构建。

## 开展真实研究

1. 在“来源资料”导入官方说明、套餐权益或授权条款的文本，或添加官方公开页面 URL。每个来源指定产品归属。上传资料会标记为用户提供、尚未核实。
2. 在对话中说明竞品、目标客群、地区、币种、团队规模和关注时间。选择“资料研究 Agent”或“研究主 Agent”时，可以不提供 URL，由 Agent 自行联网检索、采集正文并整理来源研究报告。也可以直接提供官方 URL。
3. 在输入框左下角选择数字员工，选项与“数字员工”页面的已发布员工一致。所选员工使用自己的提示词、工具权限和版本执行；研究主 Agent 可委派资料、定价、产品、策略和核验任务。执行过程、工具结果及用量保存在 SQLite。
4. 打开报告中的引用查看当时保存的原文、URL、采集时间和内容 hash；确认价格、授权与适用条件后使用结论。报告支持导出 Markdown，历史支持追问和检索。

网络检索默认使用无需额外密钥的 Bing 公开 RSS 搜索。标题与摘要只用于发现来源，必须采集正文后才能引用；无结果或搜索异常会如实返回，不会生成虚构资料。公开搜索可能限流、空返回或改变格式，需要调整检索词或直接提供官方 URL。交互研究默认最多 4 轮检索、8 个页面采集；明确指定“最多1轮检索、1个页面采集”等更小限制时，服务端会进一步收紧，并返回剩余预算。

来源采集接受用户提供、已登记、本轮检索发现或已采集页面实际链接中的公共 URL，支持静态 HTML 与文本；逐次校验重定向、公共 IPv4、标准端口及响应大小，阻止内网和元数据地址。登录页面、依赖 JavaScript 的动态价格和 PDF/OCR 尚未接入，可通过 TXT、MD、CSV、JSON 文本导入补充。页面无法访问时会报告失败，不能据此推断产品没有相关能力。

默认检索每个来源的最新已保存内容，不会自动刷新所有网页；需要当前信息时明确要求刷新，或使用定期巡检。历史原文保持不可变；可以通过 `query_evidence.evidenceIds` 读取指定版本，通过 `compare_snapshots` 比较同一来源的前后内容。采集时间不等于厂商变更生效时间。

定价候选必须绑定证据 ID 和包含金额、明确付款周期的原文片段。Decimal 计算月均、年度成本和最低席位；不自动换汇、不将年付月均当作月付、不对未知周期做假定。地区、税费、优惠资格、币种、席位授权和额度消耗口径需要结合原文核对。程序校验引用和计算，语义仍需人工复核。报告只能引用本次运行工具实际返回的证据；没有引用或子任务失败时标记为部分结果，不生成成功研究结论。

## 持续观察来源

在“任务与订阅”发布任务模板，选择 1 至 10 个已经采集的官方公开页面，设置研究要求和检查间隔。创建时以所选原文建立基线；每次检查先重新采集所有选定来源，再调用真实模型分析前后原文，会消耗模型额度。

通知基于真实原文 hash 的变化，表示“来源内容更新”。页面排版、措辞或无关内容也可能触发更新，不能直接解释为涨价、授权或产品能力变更。当前没有自动的价格百分比阈值告警，商业化含义需结合报告与前后引用核对。无变化时保持安静；采集失败、模型失败或研究不完整时通知并保留原基线。全部来源检查和研究成功后才推进基线，重复触发与重启补偿不会重复发送同一更新通知。

订阅固定创建时发布的模板与 Agent 版本，后续发布不会改变旧订阅。服务运行期间执行持久化间隔调度，关闭期间不执行，重启后合并补最近一次到期检查。显示北京时间，不是每天固定时刻的 cron。

## 数据与升级

业务数据位于 `data/workspace.sqlite`，启用 WAL、外键、FULL 同步、运行租约、工具 checkpoint 和 SSE 事件补发。退出时将未完成研究回收到队列；异常退出后等待约 30 秒租约过期再恢复，未提交的模型调用可能重发并再次计费。每次研究最多 60 次模型调用、60 次工具调用和 8 分钟运行时间。模型请求上下文限制为 75,000 字符：完整保留最近的工具调用/结果关系，超大正文使用带明确标记的摘录，保留当前任务和引用修正前的原始约束；原文与 checkpoint 不改写。早期用户约束可通过 search_history 找回。

升级首次打开数据库时，会事务性移除旧版明确标记的演示执行、虚构来源和演示订阅，并升级内置默认配置。真实模型研究、用户资料及自定义配置保留。建议在服务关闭后备份 SQLite 及其 WAL 文件，或使用 SQLite 一致性备份。旧库的少量兼容字段仍保留在磁盘结构中，不再提供资料集切换或离线执行入口。

应用面向本机个人工作空间，没有多用户身份和跨工作空间权限；不应直接开放到公网。来源、研究问题与读取的资料会提交到配置的模型服务。

## 工程与验证

| 位置 | 职责 |
| --- | --- |
| `apps/web/src/features` | 对话、来源、报告、Agent、订阅和通知 |
| `apps/server/features` | 按功能注册 HTTP API |
| `packages/agent-runtime` | 真实模型适配、ReAct、委派、租约、checkpoint、引用验证 |
| `packages/research` | Agent 定义、来源采集、证据检索、定价计算和来源巡检 |
| `packages/storage` | SQLite 迁移与仓储 |
| `tests` | HTTP 协议、可靠性、来源巡检和浏览器回归 |

```sh
pnpm typecheck
pnpm test
pnpm build
pnpm test:ui
```

测试使用临时数据库；模型和页面响应的模拟只存在于测试目录，不读取用户 `.env`、不消耗真实额度，也不会进入应用运行链路。浏览器回归使用本机 Google Chrome。自动化回归用于验证工程行为，不能证明所有产品事实或商业判断正确。

真实网络与模型评估（会消耗模型额度，使用独立临时数据库）：

```sh
RUN_LIVE_EVALUATION=1 node --import tsx tests/evaluate-live.mts
```

评估覆盖自主来源研究、历史约束检索、超长真实原文回放和取消。结果写入命令输出的临时目录，不改变默认工作空间。协议回归与真实调用结果分别记录在 [验证记录](docs/verification.md)。
